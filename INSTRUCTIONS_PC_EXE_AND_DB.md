# 📘 KidsGuard Pro — ПК-часть (`hosts_blocker.py`), живой экран компьютера и сборка `.exe`

Актуально для текущей версии скрипта (v5, один файл). Документ описывает **реальное**
поведение кода: какие процессы запускаются, где лежат файлы, как телефон получает
**живой поток экрана ПК** и почему телефон больше не разряжается за несколько часов.

---

## 1. Быстрый старт на ПК ребёнка (Windows 10/11)

1. Установите Python 3.9+ и библиотеки:
   ```bat
   pip install pillow pyinstaller
   ```
   `Pillow` нужен для **быстрого JPEG-потока** (без него программа работает, но кадры
   кодируются медленным встроенным PNG-кодером).
2. Запустите `hosts_blocker.py` **от имени администратора** (или собранный `hosts_blocker.exe`).
3. Программа сама:
   - создаёт папки и файлы (см. раздел 2);
   - регистрирует в Планировщике заданий две задачи и автозапуск агента;
   - поднимает локальную веб-панель и P2P-мост.

**Режимы запуска (флаги реального кода):**

| Команда | Кто запускает | Что делает |
|---|---|---|
| `hosts_blocker.py` | пользователь | окно управления |
| `hosts_blocker.py --engine` | Планировщик, `SYSTEM` | блокировки, лимиты, веб-панель, P2P-мост, поток экрана |
| `hosts_blocker.py --agent` | автозапуск при входе пользователя | активное окно, закрытие вкладок, снимок рабочего стола |

> Старые названия `--daemon`, `--capture-worker`, `--install-service` и задачи
> `WindowsHostsGuardDaemon` / `WindowsHostsGuardCapture` **в этой версии не используются** —
> актуальны `--engine` / `--agent` и задачи `HostsBlockerEngine` / `HostsBlockerWatchdog`.

## 2. Где хранятся данные (точные пути)

### `C:\ProgramData\HostsBlocker\` — конфигурация и служба (только администраторы/SYSTEM)
| Файл | Назначение |
|---|---|
| `config.json` | правила блокировки, лимиты, `pairing_code`, пароль панели (`salt`/`hash`), состояние блокировки ПК |
| `usage.json` | счётчики времени за день/всего |
| `reset.json` | очередь сброса счётчиков |
| `error.log` | ошибки движка |
| `bin\HostsBlockerEngine.exe` (или `.py`) | защищённая копия для задачи SYSTEM |

### `C:\ProgramData\HostsBlockerPub\` — обмен между SYSTEM и сеансом пользователя
*(у обычных пользователей есть право записи — это нужно агенту)*

| Файл | Назначение |
|---|---|
| `agent_<user>.json` | активное окно/процесс пользователя (обновляется раз в 3 с) |
| `activity_<user>.json` | накопленное время по программам и заголовкам за сегодня |
| `activity_history.json` | архив активности за последние 30 дней (пишется раз в минуту) |
| `screen.png` | последний кадр рабочего стола (по факту это JPEG, если установлен Pillow) |
| `screen_req.flag` | запрос «сними экран сейчас» от движка/телефона |
| `blocked.json` | флаги блокировки для агента |

> ❗ **Важно:** в текущей версии **нет** SQLite-файла `pc_offline_history.db`.
> Оффлайн-история на ПК хранится в JSON-файлах выше, а накопительная оффлайн-база
> (SQLite/Room) находится **на телефоне родителя** — её наполняет приложение KidsGuard.
> Устаревшие инструкции про `C:\Users\Public\HostsBlocker\pc_offline_history.db` относились
> к предыдущей архитектуре и больше не соответствуют коду.

## 3. Живой экран ПК в приложении Android

Раньше вместо потока был «слайд-шоу»: кадр раз в 3–4 секунды. Теперь работает настоящий
поток двумя путями:

### 3.1. Домашний Wi-Fi — MJPEG (плавно, без интернета)
* `POST /api/login` → cookie `hb_session` + `csrf` (пароль панели ПК);
* `GET /api/stream` → `multipart/x-mixed-replace; boundary=kidsguardframe`,
  внутри каждого кадра `Content-Type` + `Content-Length` + JPEG;
* поток живёт, пока открыт и читается; при обрыве клиента запись падает и поток
  закрывается сам (таймаут сокета 8 с).

### 3.2. Интернет (4G/5G, другая сеть) — кадры через P2P-мост
* телефон отправляет `PC_CMD` с `action=/api/stream_start` (параметры `fps`, `w`, `h`,
  `quality`, `duration`) — это **аренда потока**;
* ПК отдельным MQTT-соединением публикует `PC_STREAM_FRAME` в топик
  `kidsguard/eb6ecfcf/v34_p2p/pc_stream/<pairing_code>` (и в старый `v33_p2p`);
* формат кадра: `{"type":"PC_STREAM_FRAME","seq":N,"ts":мс,"w":800,"h":450,"fmt":"image/jpeg","b64":"..."}`;
* аренда продлевается телефоном каждые 5 с и **сама истекает через 25 с** после
  закрытия просмотра — ПК перестаёт кодировать кадры.

### 3.3. HTTP-эндпоинты панели (локальная сеть)
| Метод | Путь | Назначение |
|---|---|---|
| GET | `/api/state` | состояние ПК (облегчённый пакет) |
| GET | `/api/screen` | один кадр (Base64) |
| GET | `/api/stream` | **MJPEG-поток** |
| POST | `/api/stream_start` | продлить аренду потока, задать `fps/w/h/quality` |
| POST | `/api/stream_stop` | остановить поток |
| POST | `/api/login` | вход по паролю панели |

### 3.4. Что видит родитель в приложении
В разделе **«💻 ПК»** карточка «Живой экран ПК» показывает поток и кнопку на весь экран.
На весь экран доступны 3/5/8 кадров в секунду, пауза, снимок в галерею, запись MP4 и
блокировка ПК. В карточке есть выбор качества: **Эконом 480×270**, **Баланс 640×360**,
**HD 960×540** (чем меньше — тем меньше трафика и нагрузки на ПК/телефон).
На главном экране родителя показывается живое превью ПК на 2 к/с (профиль «Эконом»),
которое включается только пока дашборд открыт и приложение активно.

Кадры через Интернет передаются **бинарным JPEG** (4 байта seq + 8 байт времени + JPEG),
без Base64: это примерно на треть меньше трафика и без парсинга больших JSON на телефоне.
Если сеть не успевает, ПК пропускает кадры, а не копит очередь — поэтому видео не
«отстаёт» и не зависает. Подпись времени кадра берётся по часам телефона, чтобы сдвиг
часов/пояса на ПК не показывал «минус час».

Поток включается **только когда экран ПК открыт и приложение на переднем
плане**, и выключается при уходе с экрана/сворачивании.

### 3.5. Безопасность P2P (важно)
- На публичном брокере много ПК с кодом по умолчанию `101-701`, поэтому ПК публикует
  случайный `pc_id`, а приложение принимает пакеты **только своего** ПК (код + `pc_id`).
- Команды изменения правил, снимок экрана и запуск потока по P2P требуют **пароля панели ПК**
  (он вводится один раз в «⚙ Настройка подключения к ПК» и сохраняется). Без него ПК
  отвечает подсказкой и ничего не меняет.
- Рекомендуется сменить код P2P на уникальный (например `742-318`) в панели ПК и ввести его
  в приложении: так исключается даже случайное совпадение кодов.

## 4. Почему телефон раньше сильно разряжался и что исправлено

| Причина | Было | Стало |
|---|---|---|
| MediaProjection на телефоне ребёнка | виртуальный дисплей крутился 24/7, кадр копировался ~60 раз/с (аллокация Bitmap по 3 МБ) | кадры копируются только при активном просмотре, ≤2 раз/с; зеркало **отцепляется** (`setSurface(null)`), когда родитель не смотрит |
| «Живая трансляция» при каждом запуске | включалось окно на 24 часа | окно только по запросу, 90–120 с, продлевается командами просмотра |
| Отправка кадров | JPEG каждые 1.8 с + запись каждого кадра в SQLite | только при просмотре, 1 кадр/с; в оффлайн-БД кадры во время потока не пишутся |
| GPS на телефоне ребёнка | `PRIORITY_HIGH_ACCURACY` каждые 3–8 с круглосуточно | высокоточный режим 12–15 с **только пока родитель смотрит карту**, иначе 90–180 с; геокодинг/запись в БД — по перемещению (>40–60 м) или раз в 1–2 мин |
| Экран ПК | состояние + PNG каждые 3 с, история за 30 дней в каждом пакете | лёгкое состояние раз в 4 с, полная история раз в 60 с (и по запросу), снимок для превью раз в 30 с |
| База телефона | запись истории ПК в Room на каждый пакет (раз в 3 с) | только при изменении данных и не чаще раза в 15 с |

## 5. Сборка одного `.exe`

```bat
pip install pillow pyinstaller
pyinstaller --noconsole --onefile --uac-admin --name hosts_blocker hosts_blocker.py
```

* `--noconsole` — без чёрного окна консоли;
* `--onefile` — один файл (`dist\hosts_blocker.exe`);
* `--uac-admin` — запрос прав администратора при первом запуске (нужен для `hosts`,
  брандмауэра и Планировщика).

Готовый `hosts_blocker.exe` скопируйте на ПК ребёнка (например, в
`C:\ProgramData\HostsBlocker\`) и запустите один раз от администратора. Дальше программу
поднимает Планировщик (`HostsBlockerEngine`, `HostsBlockerWatchdog`) и автозапуск агента.

## 6. Если экран ПК не показывается

1. **ПК онлайн?** В приложении должен быть зелёный статус и код привязки (например `101-701`).
2. **Домашний Wi-Fi:** введите IP ПК и пароль панели в «⚙ Настройка подключения к ПК».
   Порт по умолчанию `8765`. Проверьте в браузере телефона: `http://<IP>:8765/`.
3. **Брандмауэр:** правило `HostsBlockerPanel` открывает TCP-порт только для локальной
   подсети; при смене сети проверьте, что Wi-Fi-профиль «Частный».
4. **Интернет (P2P):** оба устройства должны быть в сети, код привязки на ПК и в
   приложении — одинаковый. Публичные брокеры `broker.hivemq.com` / `broker.emqx.io`
   могут быть недоступны у провайдера — тогда работает только Wi-Fi.
5. **Пустой/чёрный кадр:** агент пользовательской сессии должен быть запущен
   (`agent_<user>.json` свежий, младше 10 с). Если ПК только что загрузился — подождите
   вход пользователя в Windows.
6. **Поток не стартует:** в `C:\ProgramData\HostsBlocker\error.log` не должно быть
   ошибок `panel:` / `p2p:`. Проверьте, что установлен `Pillow` (иначе PNG-поток будет
   очень медленным).

## 7. Быстрая проверка «всё работает»

- [ ] `config.json` создан, панель открывается по `http://127.0.0.1:8765/`;
- [ ] в диспетчере задач есть `HostsBlockerEngine` и `HostsBlockerAgent`;
- [ ] `screen.png` обновляется (время изменения);
- [ ] в приложении карточка ПК показывает поток и счётчик кадров/с;
- [ ] после закрытия экрана ПК поток гаснет (на ПК перестаёт расти нагрузка CPU).
